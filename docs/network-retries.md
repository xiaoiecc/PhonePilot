# OpenAI 请求的有限重试

瞬时网络错误不应立即终止任务。恢复只发生在一次 Responses API 请求内部：首次失败后最多重试 3 次，总计最多 4 次请求。重试使用同一输入和 previous_response_id；不会重启任务，也不会重放已经完成的手机动作。

## 什么会重试

- 可恢复的连接、读取或超时错误。
- HTTP 408、409、临时限流 429 和 5xx 服务错误。
- 使用有界指数退避；服务器提供 Retry-After 时按其要求等待。超过客户端允许的等待预算时明确停止，不提前重发。

## 什么不会重试

- API Key、权限、参数、模型/资源配置错误。
- 余额、账单、项目或组织额度限制，即使 HTTP 状态也是 429。
- 证书/主机名验证错误、协议解析错误。
- 用户停止、协程取消或运行中改向导致的主动取消。取消也会中断退避等待。

错误按 HTTP 状态、机器可读错误码和传输异常类别判断，不依据服务端正文关键词猜测。诊断不包含原始响应正文、认证头、订阅、请求内容或代理凭据。不会自动换节点，也不会绕过已启用代理改为直连。

一次传输失败只能证明未取得可用 HTTP 结果，不能仅凭通用连接错误就认定整台手机断网或归因到某个代理节点。新诊断保留脱敏后的异常类别和重试次数，便于区分 DNS、连接、超时及 TLS 等情况；旧版已丢弃的底层原因无法从历史中恢复。

公开依据：[OpenAI 错误说明](https://developers.openai.com/api/docs/guides/error-codes)、[官方 SDK 重试说明](https://developers.openai.com/api/reference/python)。
