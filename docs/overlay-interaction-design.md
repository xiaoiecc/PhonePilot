# 悬浮窗与不打扰模式交互方案

日期：2026-11-08。

状态：交互设计与实施约束，已接入 1.0.3 候选版；实际验收及未完成项以 [验证记录](capsule-background-validation-20261108.md) 为准。用户本轮明确授权改进悬浮窗设计；范围限定于悬浮窗及后台模式相关入口，不扩展为整个 App 的 UI 重做。

后台实现遵循 [后台执行技术方案](background-execution-technical-design.md)，所有实现遵循 [架构契约](architecture-contract.md)。本文不能替代其中的能力验收。

## 2. 一个悬浮控件，三种形态

| 形态 | 信息与操作 | 进入方式 |
| --- | --- | --- |
| 小球 | 状态标记；点击展开；可拖动贴边 | 用户主动收起 |
| 胶囊 | 一行当前动作、暂停/继续、停止；不显示长对话和输入框 | 正在执行的默认形态 |
| 卡片 | 保留同一头部；下方按状态展示进度、人工交互或暂停输入区 | 暂停自动展开；用户点状态行查看详情 |

运行态不再把完整 Chat、长输入框和一排按钮同时铺在手机上。详细对话仍在主 Chat，详细工具日志仍可查看；紧凑呈现不能删除用户可见的中途输出、工具记录和历史。

暂停卡片的输入框从一行起步，按实际排版行数自动长高：手动换行和文字自动折行都计入；删除文字后自然缩短。不是固定多行高度，也不是从第一行起就在固定小框里滚动。空闲时的新消息入口、模板、语音等现有能力保留，在相应卡片里呈现；已有会话的普通发送继续该会话，新建会话仍必须显式操作。

### 输入区自适应规则

- 默认内容高度为一行文字及内边距，触控区域仍至少 48dp；不预留固定的大块空白。
- 按当前宽度、字号和真实文本布局测量高度，不能按字符数或换行符数量估算。
- 每增加或减少排版行，输入区和卡片整体随之增高或缩短，顶部头部保持稳定，发送键固定对齐输入区底部。
- 初始设计上限为六行；同时受键盘上方实际可用高度约束，取两者较小值，给头部控制和用量留出空间。小屏、横屏、大字号不能照搬固定像素上限。
- 达到上限后才在输入框内部滚动，光标始终可见；删回上限以内就恢复随内容缩短。
- 输入法组合输入期间不重建编辑器、不重设文本或选择区，不因高度动画打断联想、中文组词和光标操作。

## 3. 暂停 → 输入 → 发送 → 继续

1. 点击暂停，立即提供按压反馈，向协调器发送暂停命令。
2. 卡片展开与协调器的真实状态同步；不能只改按钮文字就宣称设备动作已经停止。尚在结束当前动作时显示暂停正在生效，安全检查点之后不再执行下一动作。
3. 暂停卡片保留顶部状态与停止键，向下自然长出多行输入区。展开本身不弹键盘，用户点击输入框时才获取焦点。
4. 用户输入补充要求，按“发送”。协调器接受消息并解除本次普通暂停，继续同一会话；运行轮次是否延续由现有协调器决定，UI 不重建任务。
5. 只有发送被接受，才清空对应草稿、收起键盘和输入区，回到运行胶囊。重复点击不能发送两份。
6. 发送失败或任务已进入收尾，保留文字并显示原因，不能先清空再尝试恢复。
7. 不补充文字时，可以直接点继续；空输入不发送空消息。

退出键盘、点窗口外、折叠卡片、清空草稿均不能擅自解除手动暂停。有草稿时不进行自动折叠或销毁编辑器。停止和新建会话也不能让迟到的发送回执清掉另一个会话的草稿。

人工确认、选择、接管和文字问答继续读取同一个 `PendingInteraction`。普通补充消息不能冒充确认，也不能用“发送并继续”绕过尚未回答的交互；人工交互卡优先显示，并携带交互 ID 回答。

## 4. 信息层级和视觉

2026-11-08 补充：用户明确指出现有形状、元素和配色显旧、简陋。本次不是仅给旧面板加圆角，而是重做相关悬浮控件的视觉语言。主 App 的其他页面不因此自动进入重设计范围。

- 统一圆润表面，胶囊与卡片共用头部和圆角语言；优先实心浅色/深色表面，轻描边、轻阴影，避免文字透到底层页面。
- 运行头部只显示当前正在做的事，长句截断；展开后可看完整描述和最近进度。近期进度来自已有轨迹投影，不能另造日志执行链。
- 暂停/继续与停止采用统一圆形按钮，触控区域至少 48dp；停止始终在同一位置，不藏进二级菜单。
- 打开主 App、模板、新建会话等次要操作放到卡片中，避免在运行胶囊上排满小图标。
- 卡片右下角用较弱但可读的次级文字展示累计输入/输出 token，例如 `输入 12.3K · 输出 1.2K`；沿用 K/M 和一位小数规则，未知值不伪装成 0。不将 token 混进模型正文或每条气泡。
- 小球可降低闲置透明度；承载文字的胶囊和卡片保持清晰。状态变化兼有文字和图标，不能只靠颜色。

### 具体视觉方向

| 要素 | 新方向 |
| --- | --- |
| 形状 | 胶囊、小球和展开卡片有连续的圆角关系；内层输入区用较小圆角，不给每一行再套一层描边方框 |
| 表面 | 冷调中性色分出背景、卡片、输入区三层；取消突兀的深色标题横条，头部与正文属于同一块表面 |
| 配色 | 低饱和雾蓝作为主色，少量用于运行、继续和发送；停止使用柔和的红色底与清晰的红色图标；避免所有按钮都涂蓝或通篇高亮 |
| 图标 | 统一线宽、尺寸和光学居中的矢量图标；暂停、继续、停止等实心控制符也使用同一套比例，替换零散风格 |
| 按钮 | 可见按钮圆盘约 32–36dp，实际点击区域至少 48dp；次要动作轻量呈现，减少大块矩形按钮堆叠 |
| 字体 | 状态约 14sp 中等字重，内容约 14–16sp，说明约 12sp；用字重、间距和次级色建立层级，避免处处加粗或全白文字 |
| 留白 | 使用一致的间距尺度，靠分组和留白组织内容；减少粗边框、分隔线和重复标题 |

视觉资源使用浮窗专属语义色与尺寸，避免改全局 `primary` 等资源导致其他页面意外换色。浅/深主题成对定义，实际颜色搭配须核对文字和控件对比度；上述方向不是已通过视觉验收的成品。

## 5. 动效与窗口行为

胶囊向下展开成卡片，头部保持连续，输入区稍后淡入；发送成功反向收回。形态过渡以约 280–340ms 为起点，文字/图标变化约 120–160ms，实机根据帧表现微调。

不得每帧销毁重建悬浮窗口或重新绑定整个聊天列表；动画只改变呈现，不驱动任务状态。快速暂停/继续要从当前可见尺寸过渡到最新目标，取消旧动画，旧结束回调不能覆盖新状态。系统关闭动画时直接切换。

窗口展开保持顶部锚点，必要时根据安全区和键盘可用高度调整位置；在小屏、横屏、大字号下，正文可滚动，停止键仍可达。停止键与键盘不能被裁掉。输入焦点只在用户明确编辑时获得，退出编辑后恢复原有窗口焦点策略。

截图临时隐藏继续使用 `OverlayPolicy` 租约。动画、编辑器焦点和窗口恢复不得新增独立隐藏标记、定时器补救或第二套“是否显示”的真相。

## 6. 不打扰模式的 UI 方向

用户名称使用“不打扰模式”，说明文字为“在后台操作应用，你可以继续使用手机”。这描述目标行为，不能在能力未就绪时作为已经兑现的保证。

沿用同一套胶囊和卡片，区分执行位置，不再造一套后台任务 UI：

| 状态 | 展示 |
| --- | --- |
| 运行 | 简洁的“后台运行 · 当前应用/动作”，暂停、停止可达；允许收成小球 |
| 暂停 | 同样平滑展开输入区，发送后继续该后台任务 |
| 等待确认/接管 | 明确显示需要用户做什么；不得突然把目标应用抢到主屏 |
| 完成 | 简短结果和查看对话入口；不自动拉起主 App 或目标应用打断用户 |
| 连接失败/能力缺失 | 展示具体原因与恢复入口，不静默切换到主屏执行 |

后台运行时默认不常驻视频或整块虚拟屏预览。预览采用主动展开的方向，帧率、焦点、交互能力必须受后台技术方案约束；不能为做 UI 先接一个绕过执行器的点击预览。打开预览不隐式切换执行位置。

模式入口借鉴 DSH Go 的清晰层级：模式说明、当前能力状态、必要权限及其就绪原因。我们当前只需要现有 Shizuku 路线，不照搬对方全部通道和高级设置。

2026-11-08 用户补充要求：后台胶囊点击可将目标应用切到前台，同一任务可在前后台来回切换。运行中切换、人工接管及中途输出的设计见 [后台操控产品流程](background-mode-product-design.md)，替代此前只在启动时选位置的限制。按钮状态必须等待真实迁移回执，不能做表面可切、实际未迁移的按钮。

切换位置不等于暂停或接管：运行中的 Agent 在两个方向切换成功后均继续当前任务；切回前台用于直观看到逐步操作。原本已暂停的任务继续暂停，切换中用户发出的暂停/停止优先。

正常结束后把目标任务移回主屏后台并保留应用自身最近任务标记，沿用既定技术方案。UI 的“已完成”应在真实清理完成后显示，不能为了动画顺滑提前宣告成功。

## 7. 实现必须进入既有架构

| 职责 | 位置与约束 |
| --- | --- |
| 暂停、继续、发送接受、人工交互、任务终结 | `RunCoordinator`；命令适配层转发，不持有第二份生命周期 |
| 发送并继续 | 在协调器锁定的当前任务内完成接受与暂停原因变更，拒绝时不解除暂停；不能由浮窗顺序拼接“发送 + 恢复” |
| 展开、收起、编辑焦点、尺寸动画 | UI 呈现层；不得持有 runner 或设备执行权限 |
| 显示/关闭、最小化和截图隐藏 | `OverlayPolicy`；动画服从其最新投影 |
| 草稿 | 复用现有草稿边界，绑定会话和代次；不得异步清除另一个会话 |
| 当前动作、工具日志、用量 | 现有不可变运行/历史投影；不能轮询或从文本反推任务事实 |
| 后台屏与任务迁移 | 后台技术方案的执行后端，经既有统一入口，不属于悬浮窗能力 |

当前源码已确认的行为差距：`RunCoordinator.submit()` 接受插话后只移除 `PauseReason.DRAFT`，仍保留 `USER`；现有浮窗在运行态也一直显示输入区。因此“暂停后发送自动继续”需要协调器命令语义和 UI 投影共同修改，不能只换布局。

普通 Chat 的发送语义保持原约定，是否解除手动暂停由明确的发送并继续命令表达。人工交互的回复仍需匹配 runId/interactionId，不能被新命令绕过。

## 8. 实施与验收

先实现前台悬浮窗的三态呈现及协调器的发送并继续命令，再接入已完成验收的后台能力。前后台共用视觉组件和任务命令，后台专属部分只增加执行位置状态与必要入口。

验收必须覆盖：

- 运行时没有普通输入区；暂停展开，编辑不抢键盘，发送被接受后自动继续同一会话。
- 输入从一行随真实折行增减，达到上限才滚动；删除恢复收缩，组合输入、光标位置与键盘调整正常。
- 拒绝发送保留草稿；停止/收尾不能被旧发送唤醒；双击只接受一次。
- 草稿清空、键盘退出、折叠都不解除手动暂停；人工交互不可绕过。
- 快速暂停/恢复、旋转、窗口重建、大字号、横屏和关闭动画时状态与按钮正确。
- 运行、暂停、编辑和形态切换期间截图隐藏恢复；关闭窗口后旧动画或隐藏租约不能重新打开它。
- 用量是累计数；日志、语音、模板、历史和普通聊天功能没有丢失；新建会话仍然显式进行。
- 后台模式未就绪不伪装可用；预览与停止不抢主屏；正常退出语义与技术方案一致。

涉及执行、状态和 UI 行为的实现，按仓库要求运行核心测试、Android JVM 测试、Debug 构建、相关 lint、架构检查及受影响的实机路径；APK 保持原包名、签名和用户数据兼容。设计文档本身不表示这些验收已经通过。
